# Borrow Buddy: เอกสารออกแบบ (เวอร์ชัน 2)

เวอร์ชัน 2 ย้ายที่เก็บข้อมูลจาก localStorage ไป Supabase และเพิ่มการเข้าสู่ระบบสำหรับเจ้าของ ส่วนที่ไม่ได้กล่าวถึงยังเหมือนเวอร์ชัน 1

ศัพท์ทั้งหมดในเอกสารนี้อ้างอิงจาก [CONTEXT.md](./CONTEXT.md)

## 1. ภาพรวมและเป้าหมาย
เว็บหน้าเดียวสำหรับ **เจ้าของ** ที่เข้าสู่ระบบแล้ว ใช้บันทึกว่า **เพื่อน** ยืม **ของ** อะไร เมื่อไร ต้องคืนเมื่อไร และกดว่า **คืนแล้ว** ได้

## 2. ขอบเขต

**อยู่ในขอบเขต**
- เพิ่ม Loan, แก้ไข Loan, ดูรายการ Loan
- กดคืนแล้ว (ระบุวันที่คืนจริง) และยกเลิกการคืน
- ค้นหา/กรองตามชื่อเพื่อน
- แสดงสถานะ และจำนวนวันเกินกำหนด
- **(v2)** เข้าสู่ระบบ/ออกจากระบบด้วย email + password
- **(v2)** เก็บ Loan ใน Supabase และเห็นเฉพาะ Loan ของตัวเอง (RLS)
- **(v2)** ย้าย Loan เดิมจาก localStorage ขึ้น Supabase ครั้งเดียวหลังเข้าสู่ระบบครั้งแรก

**นอกขอบเขต**
- **(v2)** หน้าสมัครสมาชิกในเว็บ (ไม่มี บัญชีเจ้าของสร้างจาก Supabase Dashboard), ลืมรหัสผ่าน, OAuth/magic link
- เพื่อนเข้าเว็บ (เพื่อนไม่ต้องมีบัญชี)
- ลบ Loan, แจ้งเตือน, เลื่อนกำหนดคืน, รูปภาพของ
- ทะเบียนรายชื่อเพื่อน/ของแยก, การตรวจของซ้ำซ้อน
- สำรองข้อมูล/นำเข้า-ส่งออกไฟล์

## 3. เทคโนโลยี
- React + Vite, ภาษา JavaScript (ไม่ใช้ TypeScript)
- เก็บข้อมูลใน Supabase (Postgres + Auth) ผ่าน `@supabase/supabase-js`
- localStorage ใช้เฉพาะค่าธีม และเป็นแหล่งข้อมูลต้นทางสำหรับย้ายข้อมูลครั้งเดียว
- ค่าเชื่อมต่อ (URL, publishable key) อยู่ใน `.env` ผ่าน `VITE_*` ห้ามใช้ service role key ในฝั่งเว็บ
- ทดสอบด้วย Vitest

## 4. โมเดลข้อมูล

**Loan**
| ฟิลด์ | ชนิด | หมายเหตุ |
|---|---|---|
| `id` | string (uuid) | สร้างอัตโนมัติ |
| `ownerId` | string (uuid) | **(v2)** = `auth.uid()` ของเจ้าของ ตั้งค่าอัตโนมัติที่ฐานข้อมูล ไม่ให้แก้ (คอลัมน์ `owner_id`) |
| `friendName` | string | ชื่อเล่นของเพื่อน พิมพ์เองทุกครั้ง ห้ามว่าง |
| `itemName` | string | ชื่อของ ห้ามว่าง |
| `borrowedDate` | string `YYYY-MM-DD` | วันที่ยืม |
| `dueDate` | string `YYYY-MM-DD` | กำหนดคืน บังคับกรอก |
| `returnedDate` | string `YYYY-MM-DD` หรือ `null` | วันที่คืนจริง ว่างจนกว่าจะกดคืน |

ตาราง `loans` ใน Supabase ใช้ชื่อคอลัมน์ snake_case (`friend_name`, `item_name`, `borrowed_date`, `due_date`, `returned_date`, `owner_id`) วันที่เป็นชนิด `date` และแปลงเป็นชื่อฟิลด์ camelCase ข้างบนที่ชั้น `loanRepo.js`

วันที่เก็บเป็น ค.ศ. แบบ ISO และแสดงผลเป็น พ.ศ. เท่านั้น (เช่น 24 ก.ย. 2569) สถานะและจำนวนวันเกินกำหนดไม่เก็บ คำนวณจากวันที่ทุกครั้ง

## 5. กติกา

**สถานะ** (คำนวณจากวันนี้)
- **คืนแล้ว**: `returnedDate` ไม่เป็น null
- **เกินกำหนด**: ยังไม่คืน และวันนี้ > `dueDate`
- **ยังไม่คืน**: ยังไม่คืน และวันนี้ ≤ `dueDate` (ถึงกำหนดวันนี้พอดียังไม่เกิน)

**จำนวนวันเกินกำหนด** = วันนี้ − `dueDate` (นับเป็นวัน ใช้กับ Loan ที่เกินกำหนดเท่านั้น)

**การตรวจวันที่** (ปฏิเสธการบันทึกเมื่อผิดกติกา พร้อมข้อความภาษาไทย)
- `dueDate` ต้องไม่ก่อน `borrowedDate`
- `returnedDate` ต้องไม่ก่อน `borrowedDate`
- ชื่อเพื่อนและชื่อของห้ามว่าง

**การกดคืนแล้ว**
- ค่าเริ่มต้นของวันที่คืนจริงคือวันนี้ แก้เป็นวันย้อนหลังได้
- ยกเลิกการคืนได้ (ตั้ง `returnedDate` กลับเป็น null)

## 6. หน้าจอ (หน้าเดียว)

- **(v2) หน้าเข้าสู่ระบบ** แสดงเมื่อยังไม่มี session: email, password, ปุ่มเข้าสู่ระบบ, ข้อความผิดพลาดภาษาไทย (ไม่บอกว่า email หรือ password ผิดข้อใด) ไม่มีปุ่ม/ลิงก์สมัครสมาชิก
- **(v2)** เมื่อเข้าสู่ระบบแล้วเห็นหน้า Loan ตามเดิม พร้อมปุ่ม **ออกจากระบบ** และสถานะกำลังโหลด/บันทึก/ผิดพลาดเป็นภาษาไทย
- **(v2.1) แท็บ** แบ่งหน้าเป็น 4 แท็บตามลำดับ **เกินกำหนด → ยังไม่คืน → คืนแล้ว → เพิ่มการยืม** สามแท็บแรกแสดงจำนวน Loan ในแท็บ (นับตามผลค้นหา) และแสดงรายการของสถานะนั้นเท่านั้น แท็บเริ่มต้นคือแท็บแรกที่มี Loan (ถ้าไม่มีเลยให้เป็น ยังไม่คืน) และเมื่อเจ้าของเลือกแท็บเองให้ยึดตามที่เลือก
- แถบแท็บบนมือถือ (จอแคบ) ติดขอบล่างของจอให้กดด้วยนิ้วโป้งง่าย บนจอกว้างอยู่ใต้หัวเรื่อง พื้นที่กดอย่างน้อย 44px และเป็นสี/ข้อความ/ตัวเลขกำกับ ใช้ `role="tablist"`/`tab`/`tabpanel` และ `aria-selected`
- **ฟอร์ม Loan** อยู่ในแท็บ **เพิ่มการยืม** ใช้ทั้งเพิ่มและแก้ไข: เพื่อน, ของ, วันที่ยืม (ค่าเริ่มต้นวันนี้), กำหนดคืน กดแก้ไขที่รายการแล้วสลับมาแท็บนี้พร้อมข้อมูลขึ้นฟอร์ม (ชื่อแท็บเป็น **แก้ไขการยืม**) มีปุ่มยกเลิกการแก้ไข บันทึกหรือยกเลิกแล้วกลับไปแท็บที่ดูอยู่ก่อนแก้ไข ส่วนเพิ่มใหม่สำเร็จให้ไปแท็บตามสถานะของ Loan ที่เพิ่ม
- **ช่องค้นหา/กรอง** ตามชื่อเพื่อน อยู่เหนือรายการในสามแท็บรายการ (ไม่แสดงในแท็บเพิ่มการยืม) และค่าที่พิมพ์คงอยู่เมื่อสลับแท็บ
- **รายการ Loan** ของแท็บที่เลือก เรียงตามกำหนดคืนใกล้สุดก่อน ถ้าแท็บว่างแสดงข้อความภาษาไทยบอกว่าไม่มีรายการในสถานะนั้น
- แต่ละรายการแสดง: ชื่อของ, ชื่อเพื่อน, วันที่ยืม, กำหนดคืน, สถานะ, จำนวนวันเกินกำหนด (เฉพาะเกินกำหนด), วันที่คืนจริง (เฉพาะคืนแล้ว)
- ปุ่มต่อรายการ: **คืนแล้ว** (เฉพาะที่ยังไม่คืน), **ยกเลิกการคืน** (เฉพาะที่คืนแล้ว), **แก้ไข**
- ไม่มีปุ่มลบ

**การแสดงผล**
- ภาษาไทยทั้งหมด, วันที่ พ.ศ.
- รองรับหน้าจอมือถือ (layout ยืดหยุ่น, ออกแบบมือถือเป็นหลัก, ช่องกรอกและปุ่มสูงอย่างน้อย 44px)
- **(v2.1) สีสัน:** หัวเรื่องเป็นแถบไล่สี พื้นหลังหน้าเป็นไล่สีอ่อนนุ่ม (โหมดมืดเป็นไล่สีเข้ม) การ์ดและแท็บมีสีประจำสถานะ (เกินกำหนด=แดง/ชมพู, ยังไม่คืน=เหลืองอำพัน, คืนแล้ว=เขียว, เพิ่มการยืม=ม่วง) ต้องอ่านง่ายและคอนทราสต์พอทั้งโหมดสว่างและมืด
- โหมดมืด สลับได้ด้วยปุ่ม และจำค่าที่เลือกไว้
- ใช้สี/ข้อความแยกสถานะให้ชัด ไม่พึ่งสีอย่างเดียว

## 8. การเก็บข้อมูลและความปลอดภัย (v2)

**ตาราง `loans`** คอลัมน์ตามข้อ 4, `owner_id uuid not null default auth.uid()` อ้างอิง `auth.users(id)`

**RLS** เปิดใช้กับตาราง `loans`
- `SELECT`, `INSERT`, `UPDATE`: เฉพาะ role `authenticated` และแถวที่ `owner_id = auth.uid()` (INSERT ใช้ `with check`, UPDATE ใช้ทั้ง `using` และ `with check` กันการเปลี่ยนเจ้าของแถว)
- **ไม่มี policy `DELETE`** ทำให้ลบ Loan ไม่ได้ทั้งจากเว็บและ API (ตรงกับกติกาไม่มีการลบ)
- role `anon` ไม่มีสิทธิ์อ่าน/เขียนตารางนี้เลย
- ฐานข้อมูลตรวจซ้ำ: `due_date >= borrowed_date`, `returned_date` เป็น null หรือ `>= borrowed_date`, ชื่อเพื่อน/ของไม่ว่าง (ตรวจฝั่งเว็บด้วย `loanRules.js` เพื่อแสดงข้อความไทย)

**การยืนยันตัวตน**
- Supabase Auth แบบ email + password สร้างบัญชีเจ้าของด้วยตนเองจาก Dashboard (Add user)
- **การตัดสินใจ (2026-09-25):** ยังเปิด "Allow new users to sign up" ไว้ตามเดิม (ยอมรับความเสี่ยง) เว็บไม่มีหน้าสมัคร แต่ใครก็เรียก API สมัครบัญชีได้ บัญชีใหม่เห็นเฉพาะ Loan ของตัวเองเพราะ RLS จึงไม่เห็นข้อมูลของเจ้าของ แต่ไม่ใช่ระบบเจ้าของคนเดียวอย่างเข้มงวด หากต้องการเข้มงวดให้ปิดตัวเลือกนี้ใน Dashboard (Authentication → Sign In / Providers)
- เว็บเรียกเฉพาะ `signInWithPassword` และ `signOut` ไม่เรียก `signUp`
- session จัดการโดย supabase-js (เก็บในเบราว์เซอร์) ตอนเปิดหน้าให้ตรวจ session ก่อนแสดงข้อมูล

**การโหลด/บันทึก**
- โหลด Loan ของตัวเองหลังมี session, เพิ่ม/แก้/กดคืน/ยกเลิกคืนเป็นการเขียนไปที่ Supabase แล้วอัปเดตหน้าจอเมื่อสำเร็จ
- เขียนไม่สำเร็จ (ออฟไลน์, session หมดอายุ, RLS ปฏิเสธ) ให้แจ้งเป็นภาษาไทยและไม่ทิ้งข้อมูลที่กรอกไว้ในฟอร์ม; session หมดอายุให้กลับหน้าเข้าสู่ระบบ

**การย้ายข้อมูลจาก localStorage (ครั้งเดียว)**
- หลังเข้าสู่ระบบ ถ้ามี Loan เดิมใน localStorage คีย์เวอร์ชัน 1 และตารางของเจ้าของยังว่าง ให้ถามเจ้าของก่อนว่าจะนำเข้าหรือไม่
- นำเข้าสำเร็จทั้งหมดจึงทำเครื่องหมายว่าย้ายแล้ว **ไม่ลบ** ข้อมูลใน localStorage เอง; ถ้านำเข้าไม่สำเร็จ ข้อมูลเดิมต้องไม่เสียหาย
- Loan ที่ไม่ผ่านการตรวจ (`loanRules.js`) ให้รายงานเป็นภาษาไทยและข้าม ไม่หยุดทั้งชุด
- JSON เสียหรืออ่านไม่ได้: แจ้งเจ้าของ ไม่นำเข้า ไม่เขียนทับ

## 9. การทดสอบ (Vitest เฉพาะตรรกะใน `lib/`)
- สถานะ: ยังไม่คืน / เกินกำหนด / คืนแล้ว
- ขอบเขต: วันนี้ = กำหนดคืน ต้องเป็นยังไม่คืน, วันถัดไปต้องเป็นเกินกำหนด
- จำนวนวันเกินกำหนด
- การตรวจวันที่ทุกกรณีที่ผิดกติกา
- การจัดกลุ่มและเรียงลำดับ
- การแปลงวันที่เป็น พ.ศ.
- การกรองตามชื่อเพื่อน
- **(v2.1)** `loanTabs.js`: แท็บเริ่มต้น (แท็บแรกที่มี Loan, ถ้าไม่มีเลยเป็น ยังไม่คืน) และแท็บตามสถานะ
- **(v2)** การแปลง snake_case <-> camelCase ใน `loanRepo.js` (ตรรกะแปลงล้วน แยกจากการเรียกเครือข่าย)
- **(v2)** `legacyImport.js`: อ่านข้อมูลเดิม, JSON เสีย, Loan ที่ไม่ผ่านการตรวจ
- **(v2)** RLS ตรวจด้วยมือ/สคริปต์กับ Supabase จริง (ดู Tasks.md เฟส 5): ผู้ใช้อื่นไม่เห็น/แก้ Loan ของเรา, anon อ่านไม่ได้, ลบไม่ได้

## 10. ประเด็นที่ตั้งใจไม่ทำ
สำรองข้อมูล/ส่งออก, ลบ Loan (v2 ยังไม่มี และ RLS ไม่เปิดสิทธิ์ลบ), แจ้งเตือน, เลื่อนกำหนด, รูปภาพ, ทะเบียนเพื่อน/ของ, หน้าสมัครสมาชิกในเว็บ, ลืมรหัสผ่าน หากต้องการในอนาคตให้ทบทวน CONTEXT.md ก่อน
