# Borrow Buddy: Design

โทนหน้าตาและพฤติกรรมของหน้าจอ ศัพท์ทั้งหมดใช้ตาม @CONTEXT.md ส่วน stack และกฎเขียนโค้ดอยู่ใน @CLAUDE.md ไฟล์นี้ไม่ซ้ำสองไฟล์นั้น

ข้อที่ระบุว่า **(ค่าเริ่มต้น)** คือผมตั้งให้เองโดยยังไม่ได้ถามคุณ แก้ได้ทุกข้อ

## โทนโดยรวม

- เรียบ สะอาด ใช้งานจริง พื้นหลังเทาอ่อนเกือบขาว ตัวหนังสืออ่านง่าย ไม่ตกแต่งเกินจำเป็น
- โหมดสว่างอย่างเดียว ไม่มี dark mode
- ใช้ได้ดีบนมือถือเป็นหลัก **(ค่าเริ่มต้น)** เนื้อหาอยู่กลางจอ กว้างไม่เกินประมาณ 42rem บนจอใหญ่ ปุ่มที่กดบ่อยสูงอย่างน้อย 44px
- ข้อความบนหน้าเว็บเป็นภาษาไทยล้วน ตามป้ายใน CONTEXT.md

## ฟอนต์

- Noto Sans Thai โหลดผ่าน `next/font/google` ไม่ต้องติดตั้ง package เพิ่ม
- น้ำหนัก 400 สำหรับเนื้อความ 600 สำหรับชื่อ Item และปุ่ม
- ขนาดตัวอักษรเนื้อความไม่ต่ำกว่า 16px

สีหลักเป็นเขียวมินต์/เขียวเทา กำหนดเป็นค่าใน Tailwind theme ไม่ฮาร์ดโค้ดกระจายตามคอมโพเนนต์

| ขอบ | `#DDE5E2` | ขอบการ์ด เส้นคั่น |

ค่าเหล่านี้เลือกให้ตัวหนังสือต่อพื้นหลังมี contrast ตั้งแต่ 4.5:1 ขึ้นไป (ตัวหนังสือสีขาวบนปุ่มสีหลักผ่านเกณฑ์) ถ้าเปลี่ยนสีต้องเช็กเกณฑ์นี้ซ้ำ

สีเขียวสงวนไว้ให้ปุ่มหลักและจุดเน้นเท่านั้น **ห้ามใช้สีเขียวแทนความหมาย "คืนแล้ว"** สถานะ Returned ใช้เทาจางลงกับเครื่องหมายถูก และ Overdue ใช้แดง สถานะต้องไม่พึ่งสีอย่างเดียว ต้องมีข้อความหรือไอคอนกำกับเสมอ

## โครงหน้า (`app/page.js` หน้าเดียว)

จากบนลงล่าง:

1. **หัวเว็บ** ชื่อ "Borrow Buddy" และปุ่มหลัก "เพิ่มรายการยืม"
2. **ฟอร์ม** อยู่ใต้หัวเว็บ ซ่อนอยู่จนกดปุ่ม "เพิ่มรายการยืม" แล้วกางออกเหนือรายการ กดบันทึกเสร็จให้พับกลับ
3. **แท็บ** สองแท็บ "ยังไม่คืน" กับ "คืนแล้ว" แต่ละแท็บมีตัวเลขจำนวน Loan กำกับ เปิดหน้ามาเป็นแท็บ "ยังไม่คืน" เสมอ
4. **รายการ** การ์ด 1 ใบต่อ 1 Loan

## ฟอร์ม Loan

ใช้ฟอร์มเดียวกันทั้งตอนเพิ่มและตอนแก้ไข

| ช่อง | ป้าย | หมายเหตุ |
| --- | --- | --- |
| Item | ของที่ยืม | ข้อความ ต้องกรอก |
| Borrower | ชื่อคนยืม | ข้อความ ต้องกรอก |
| Borrowed Date | วันที่ยืม | ค่าเริ่มต้นคือวันนี้ เลือกย้อนหลังได้ |
| Due Date | วันกำหนดคืน | ต้องกรอก และต้องไม่ก่อนวันที่ยืม |
| Return Date | คืนเมื่อ | โผล่เฉพาะตอนแก้ Loan ที่ Returned |

- ข้อความเตือนขึ้นใต้ช่องที่ผิด เป็นภาษาไทย ไม่ใช้ `alert()`
  - ช่องว่าง: "กรอกช่องนี้ด้วย"
  - Due Date ก่อน Borrowed Date: "วันกำหนดคืนต้องไม่ก่อนวันที่ยืม"
- ปุ่ม "บันทึก" (สีหลัก) และ "ยกเลิก" (แบบเส้นขอบ)

## การ์ด Loan

**เนื้อหาบนการ์ด**
- บรรทัดบน: ชื่อ Item ตัวหนา และเมนู `⋯` มุมขวาบน
- บรรทัดรอง: "ยืมโดย {Borrower}"
- วันที่ 2 บรรทัด: "ยืมเมื่อ {Borrowed Date}" และ "กำหนดคืน {Due Date}"
- Loan ที่ Returned เพิ่มบรรทัด "คืนเมื่อ {Return Date}"
- วันที่แสดงแบบ `24 ก.ย. 2569` (ปี พ.ศ. เดือนย่อ ใช้ `Intl.DateTimeFormat` locale `th-TH`)

**ปุ่มบนการ์ด**
- Active: ปุ่มหลักเต็มความกว้าง "คืนแล้ว"
- Returned: ปุ่มรองเต็มความกว้าง "ยกเลิกการคืน" (กดแล้ว Loan กลับเป็น Active ทันที)
- เมนู `⋯` มีสองรายการ "แก้ไข" กับ "ลบ"
- กด "ลบ" แล้วการ์ดเปลี่ยนเป็นข้อความ "แน่ใจไหม" กับปุ่ม "ลบ" (สีแดง) และ "ยกเลิก" ในตัวการ์ดเอง ไม่ใช้ `confirm()`

**หน้าตาตามสถานะ**

| สถานะ | หน้าตา |
| --- | --- |
| Active | การ์ดพื้นขาว ขอบ `#DDE5E2` |
| Overdue | เหมือน Active แต่มีแถบสีแดงหนา 4px ที่ขอบซ้าย และป้าย "เลยกำหนด {X} วัน" สีแดงบนพื้นแดงอ่อน |
| Returned | พื้น `#F1F4F3` ตัวหนังสือเทาจางลง มีเครื่องหมายถูกหน้าชื่อ Item |

- {X} คือจำนวนวันระหว่าง Due Date กับวันนี้ ถ้า Due Date คือวันนี้ ยังไม่ถือว่า Overdue
- ห้ามเปลี่ยนสีพื้นทั้งใบเป็นแดง เพราะถ้ามี Overdue หลายใบ หน้าจอจะแดงทั้งหน้า

## การเรียงลำดับ

- แท็บ "ยังไม่คืน": Overdue ขึ้นก่อน (เลยมากที่สุดอยู่บนสุด) แล้วตามด้วย Loan ที่เหลือเรียงตาม Due Date จากใกล้ไปไกล
- แท็บ "คืนแล้ว": เรียงตาม Return Date ล่าสุดอยู่บนสุด

## หน้าว่าง **(ค่าเริ่มต้น)**

- แท็บ "ยังไม่คืน" ที่ไม่มี Loan: "ตอนนี้ไม่มีของที่ถูกยืมอยู่" พร้อมชี้ไปที่ปุ่ม "เพิ่มรายการยืม"
- แท็บ "คืนแล้ว" ที่ไม่มี Loan: "ยังไม่มีรายการที่คืนแล้ว"

## ข้อมูลและฟังก์ชันใน `lib/loans.js`

หน้าจอเรียกที่เก็บข้อมูลผ่านไฟล์นี้เท่านั้น ตามกฎใน CLAUDE.md ฟังก์ชันมี 6 ตัว:

| ฟังก์ชัน | หน้าที่ |
| --- | --- |
| `getLoans` | คืนรายการ Loan ทั้งหมด |
| `addLoan` | เพิ่ม Loan ใหม่ |
| `updateLoan` | แก้ช่องใดก็ได้ของ Loan (รวมถึงแก้ Due Date และ Return Date) |
| `deleteLoan` | ลบ Loan |
| `markReturned` | ตั้ง Loan เป็น Returned พร้อม Return Date เป็นวันนี้ |
| `unmarkReturned` | ยกเลิกการคืน ล้าง Return Date ทำให้ Loan กลับเป็น Active |

รูปแบบข้อมูลของ Loan 1 รายการ:

- `id`
- `item`
- `borrower`
- `borrowedDate`
- `dueDate`
- `returnDate` เป็น `null` เมื่อ Active

วันที่เก็บเป็นข้อความรูปแบบ `YYYY-MM-DD` (ปี ค.ศ. เฉพาะวัน ไม่มีเวลา) แปลงเป็น พ.ศ. เฉพาะตอนแสดงผล สถานะ Active/Returned ดูจาก `returnDate` และ Overdue คำนวณจาก `dueDate` เทียบกับวันนี้ ไม่เก็บเป็นช่องข้อมูล ตามนิยามใน CONTEXT.md

### แผนย้ายไป Supabase (Phase 2)

ที่เก็บข้อมูลเริ่มที่ localStorage ใน Phase 1 แล้วย้ายไป Supabase ใน Phase 2 โดยส่วนที่จัดการ Loan แก้เฉพาะ `lib/loans.js` หน้าจอที่แสดง Loan ไม่ต้องแก้ (มีเพิ่มเฉพาะหน้าล็อกอินและปุ่มออกจากระบบ ดูหัวข้อ "ล็อกอิน") ข้อกำหนดที่ต้องทำตั้งแต่ Phase 1:

- **ทุกฟังก์ชันคืน Promise ตั้งแต่ Phase 1** (เขียนเป็น `async` แม้ localStorage จะเป็น sync) เพราะ Supabase เป็น async ถ้า Phase 1 คืนค่าตรงๆ ตอนย้ายจะต้องแก้ทุกหน้าจอที่เรียก ซึ่งขัดกับกฎใน CLAUDE.md
- หน้าจอต้องรองรับสถานะ "กำลังโหลด" และ "บันทึกไม่สำเร็จ" ตั้งแต่ Phase 1 (ข้อความเตือนเป็นภาษาไทยขึ้นบนหน้า ไม่ใช้ `alert()`) เพราะตอนใช้ Supabase สองสถานะนี้เกิดขึ้นจริง
- รูปแบบข้อมูลที่ฟังก์ชันคืนต้องเหมือนเดิมทุกอย่าง (ชื่อช่องแบบ camelCase ตามข้างบน) ตาราง `loans` ใน Supabase ใช้ชื่อคอลัมน์แบบ snake_case (`borrowed_date`, `due_date`, `return_date`) และ `lib/loans.js` เป็นตัวแปลงชื่อช่อง
- ชนิดคอลัมน์วันที่เป็น `date` (ไม่มีเวลา) ให้ตรงกับ Borrowed Date, Due Date และ Return Date ที่เก็บเฉพาะวัน

**ตัดสินใจแล้ว:**

- **ข้อมูลเดิมใน localStorage ไม่ย้ายขึ้น Supabase** เริ่มใหม่ตอนขึ้น Phase 2 ไม่ต้องมีขั้นตอนนำเข้า
- **Phase 2 มีระบบล็อกอินแบบง่ายผ่าน Supabase Auth** เพื่อให้เฉพาะ Owner เข้าถึงข้อมูลได้ รายละเอียดอยู่ในหัวข้อถัดไป

## ล็อกอิน (Phase 2 เท่านั้น)

Phase 1 ไม่มีล็อกอิน เพราะข้อมูลอยู่ในเบราว์เซอร์ของ Owner เอง ล็อกอินเริ่มพร้อมกับการย้ายไป Supabase

**หลักการ**
- ผู้ใช้มีคนเดียวคือ Owner เพื่อนไม่มีบัญชีและไม่เข้าระบบ ตามที่ตกลงใน CONTEXT.md
- วิธีล็อกอินคืออีเมลกับรหัสผ่านผ่าน Supabase Auth **(ค่าเริ่มต้น)** ไม่ใช้ magic link หรือ social login เพราะมีผู้ใช้คนเดียวและตั้งค่าน้อยที่สุด
- **ไม่มีหน้าสมัครสมาชิก** สร้างบัญชี Owner เองใน Supabase dashboard ครั้งเดียว และปิดการสมัครสมาชิก (sign-ups) ในการตั้งค่า Auth ของ Supabase เพื่อไม่ให้คนอื่นสมัครเองได้
- ไม่มีหน้ารีเซ็ตรหัสผ่านในแอป ถ้าลืมให้รีเซ็ตจาก Supabase dashboard **(ค่าเริ่มต้น)**

**ความปลอดภัยของข้อมูล**
- เปิด Row Level Security ที่ตาราง `loans` และให้ Loan แต่ละแถวผูกกับบัญชีเจ้าของ (คอลัมน์ `user_id`) นโยบายอนุญาตให้อ่าน เพิ่ม แก้ ลบ ได้เฉพาะแถวที่ `user_id` ตรงกับผู้ล็อกอิน คอลัมน์ `user_id` เป็นเรื่องภายในของ `lib/loans.js` ไม่โผล่ในรูปแบบข้อมูลที่ฟังก์ชันคืนให้หน้าจอ
- ไม่มีการล็อกอิน = ไม่เห็นข้อมูลเลย แม้จะรู้คีย์สาธารณะของ Supabase

**หน้าจอ**
- ยังไม่ล็อกอิน: แสดงหน้าล็อกอินแทนหน้ารายการ มีชื่อ "Borrow Buddy" ช่อง "อีเมล" ช่อง "รหัสผ่าน" และปุ่มหลัก "เข้าสู่ระบบ" ใช้สี ฟอนต์ และปุ่มชุดเดียวกับหน้าอื่น
- ข้อความผิดพลาดเป็นภาษาไทยขึ้นใต้ฟอร์ม ไม่ใช้ `alert()` และไม่บอกว่าผิดที่อีเมลหรือรหัสผ่าน: "อีเมลหรือรหัสผ่านไม่ถูกต้อง"
- ล็อกอินแล้ว: หัวเว็บมีปุ่มรอง "ออกจากระบบ" ข้างปุ่ม "เพิ่มรายการยืม" **(ค่าเริ่มต้น)**
- ตอนเปิดหน้าและกำลังตรวจว่าล็อกอินอยู่ไหม ให้แสดงสถานะ "กำลังโหลด" ไม่แวบหน้าล็อกอินก่อน
- Session หมดอายุระหว่างใช้งาน: กลับไปหน้าล็อกอินพร้อมข้อความ "เซสชันหมดอายุ กรุณาเข้าสู่ระบบอีกครั้ง"

**ฟังก์ชันใน `lib/auth.js` (ไฟล์ใหม่ สร้างใน Phase 2)**

| ฟังก์ชัน | หน้าที่ |
| --- | --- |
| `getSession` | บอกว่าตอนนี้ล็อกอินอยู่ไหม |
| `signIn` | ล็อกอินด้วยอีเมลกับรหัสผ่าน |
| `signOut` | ออกจากระบบ |

หน้าจอเรียกเรื่องล็อกอินผ่านไฟล์นี้เท่านั้น เช่นเดียวกับที่เรียกข้อมูล Loan ผ่าน `lib/loans.js`

## นอกขอบเขตของหน้าตา

ไม่มี dark mode ไม่มีระบบล็อกอินใน Phase 1 (Phase 2 มีล็อกอินสำหรับ Owner คนเดียว ไม่มีหน้าสมัครสมาชิกและไม่มีหน้ารีเซ็ตรหัสผ่าน) ไม่มีการแจ้งเตือน ไม่มีหน้าจัดการเพื่อนหรือทะเบียน Item ไม่มีช่องหมายเหตุ ตามที่ตกลงใน CONTEXT.md และ CLAUDE.md
