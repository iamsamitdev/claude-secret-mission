# Borrow Buddy: เอกสารออกแบบ

ศัพท์ทั้งหมดในเอกสารนี้อ้างอิงจาก [CONTEXT.md](./CONTEXT.md)

## 1. ภาพรวมและเป้าหมาย
เว็บหน้าเดียวสำหรับ **เจ้าของ** คนเดียว ใช้บันทึกว่า **เพื่อน** ยืม **ของ** อะไร เมื่อไร ต้องคืนเมื่อไร และกดว่า **คืนแล้ว** ได้

## 2. ขอบเขต

**อยู่ในขอบเขต**
- เพิ่ม Loan, แก้ไข Loan, ดูรายการ Loan
- กดคืนแล้ว (ระบุวันที่คืนจริง) และยกเลิกการคืน
- ค้นหา/กรองตามชื่อเพื่อน
- แสดงสถานะ และจำนวนวันเกินกำหนด

**นอกขอบเขต (เวอร์ชันแรก)**
- ระบบล็อกอิน (เจ้าของคนเดียว เพื่อนไม่ต้องเข้าเว็บ)
- ลบ Loan, แจ้งเตือน, เลื่อนกำหนดคืน, รูปภาพของ
- ทะเบียนรายชื่อเพื่อน/ของแยก, การตรวจของซ้ำซ้อน
- สำรองข้อมูล/นำเข้า-ส่งออกไฟล์

## 3. เทคโนโลยี
- React + Vite, ภาษา JavaScript (ไม่ใช้ TypeScript)
- เก็บข้อมูลใน localStorage ของเบราว์เซอร์
- ทดสอบด้วย Vitest

## 4. โมเดลข้อมูล

**Loan**
| ฟิลด์ | ชนิด | หมายเหตุ |
|---|---|---|
| `id` | string | สร้างอัตโนมัติ |
| `friendName` | string | ชื่อเล่นของเพื่อน พิมพ์เองทุกครั้ง ห้ามว่าง |
| `itemName` | string | ชื่อของ ห้ามว่าง |
| `borrowedDate` | string `YYYY-MM-DD` | วันที่ยืม |
| `dueDate` | string `YYYY-MM-DD` | กำหนดคืน บังคับกรอก |
| `returnedDate` | string `YYYY-MM-DD` หรือ `null` | วันที่คืนจริง ว่างจนกว่าจะกดคืน |

วันที่เก็บเป็น ค.ศ. แบบ ISO และแสดงผลเป็น พ.ศ. เท่านั้น (เช่น 24 ก.ย. 2569) สถานะและจำนวนวันเกินกำหนดไม่เก็บ คำนวณจากวันที่ทุกครั้ง

## 5. กติกา

**สถานะ** (คำนวณจากวันนี้)
- **คืนแล้ว**: `returnedDate` ไม่เป็น null
- **เกินกำหนด**: ยังไม่คืน และวันนี้ > `dueDate`
- **ยังไม่คืน**: ยังไม่คืน และวันนี้ ≤ `dueDate` (ถึงกำหนดวันนี้พอดียังไม่เกิน)

**จำนวนวันเกินกำหนด** = วันนี้ − `dueDate` (นับเป็นวัน ใช้กับ Loan ที่เกินกำหนดเท่านั้น)

**การตรวจวันที่** (ปฏิเสธการบันทึกเมื่อผิดกติกา พร้อมข้อความภาษาไทย)
- `dueDate` ต้องไม่ก่อน `borrowedDate`
- `returnedDate` ต้องไม่ก่อน `borrowedDate`
- ชื่อเพื่อนและชื่อของห้ามว่าง

**การกดคืนแล้ว**
- ค่าเริ่มต้นของวันที่คืนจริงคือวันนี้ แก้เป็นวันย้อนหลังได้
- ยกเลิกการคืนได้ (ตั้ง `returnedDate` กลับเป็น null)

## 6. หน้าจอ (หน้าเดียว)

- **ฟอร์ม Loan** ด้านบน ใช้ทั้งเพิ่มและแก้ไข: เพื่อน, ของ, วันที่ยืม (ค่าเริ่มต้นวันนี้), กำหนดคืน กดแก้ไขที่รายการแล้วข้อมูลขึ้นฟอร์ม มีปุ่มยกเลิกการแก้ไข
- **ช่องค้นหา/กรอง** ตามชื่อเพื่อน
- **รายการ Loan** ด้านล่าง แยกกลุ่มตามลำดับ **เกินกำหนด → ยังไม่คืน → คืนแล้ว** แต่ละกลุ่มเรียงตามกำหนดคืนใกล้สุดก่อน
- แต่ละรายการแสดง: ชื่อของ, ชื่อเพื่อน, วันที่ยืม, กำหนดคืน, สถานะ, จำนวนวันเกินกำหนด (เฉพาะเกินกำหนด), วันที่คืนจริง (เฉพาะคืนแล้ว)
- ปุ่มต่อรายการ: **คืนแล้ว** (เฉพาะที่ยังไม่คืน), **ยกเลิกการคืน** (เฉพาะที่คืนแล้ว), **แก้ไข**
- ไม่มีปุ่มลบ

**การแสดงผล**
- ภาษาไทยทั้งหมด, วันที่ พ.ศ.
- รองรับหน้าจอมือถือ (layout ยืดหยุ่น)
- โหมดมืด สลับได้ด้วยปุ่ม และจำค่าที่เลือกไว้
- ใช้สี/ข้อความแยกสถานะให้ชัด ไม่พึ่งสีอย่างเดียว

## 7. โครงสร้างโค้ด (ระดับโฟลเดอร์)

แยกตรรกะล้วนออกจาก UI เพื่อให้ทดสอบง่าย

```
borrow-buddy/
├── CONTEXT.md
├── design.md
├── package.json
├── index.html
└── src/
    ├── main.jsx
    ├── App.jsx              # ประกอบหน้า เก็บ state ของ Loan
    ├── components/
    │   ├── LoanForm.jsx
    │   ├── LoanList.jsx
    │   ├── LoanItem.jsx
    │   ├── SearchBox.jsx
    │   └── ThemeToggle.jsx
    └── lib/
        ├── loanRules.js     # สถานะ, จำนวนวันเกิน, ตรวจวันที่, เรียง/จัดกลุ่ม
        ├── dateFormat.js    # แปลง ISO ค.ศ. เป็นข้อความ พ.ศ.
        └── storage.js       # อ่าน/เขียน localStorage
```

ฟังก์ชันใน `lib/` รับ "วันนี้" เป็นพารามิเตอร์ ไม่เรียกเวลาจริงข้างใน เพื่อให้ทดสอบได้แน่นอน

## 8. การเก็บข้อมูล
- คีย์เดียวใน localStorage เก็บอาร์เรย์ของ Loan เป็น JSON
- บันทึกทุกครั้งที่ Loan เปลี่ยน โหลดตอนเปิดหน้า
- ถ้าอ่านไม่ได้หรือ JSON เสีย ให้เริ่มด้วยรายการว่างและแจ้งเจ้าของเป็นภาษาไทย ห้ามเขียนทับข้อมูลเดิมโดยไม่แจ้ง
- ข้อมูลอยู่เฉพาะเครื่อง/เบราว์เซอร์นี้ (ล้างข้อมูลเบราว์เซอร์แล้วหาย)

## 9. การทดสอบ (Vitest เฉพาะตรรกะใน `lib/`)
- สถานะ: ยังไม่คืน / เกินกำหนด / คืนแล้ว
- ขอบเขต: วันนี้ = กำหนดคืน ต้องเป็นยังไม่คืน, วันถัดไปต้องเป็นเกินกำหนด
- จำนวนวันเกินกำหนด
- การตรวจวันที่ทุกกรณีที่ผิดกติกา
- การจัดกลุ่มและเรียงลำดับ
- การแปลงวันที่เป็น พ.ศ.
- การกรองตามชื่อเพื่อน

## 10. ประเด็นที่ตั้งใจไม่ทำ
สำรองข้อมูล, ลบ Loan, แจ้งเตือน, เลื่อนกำหนด, รูปภาพ, ทะเบียนเพื่อน/ของ หากต้องการในอนาคตให้ทบทวน CONTEXT.md ก่อน
