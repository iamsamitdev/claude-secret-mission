# Borrow Buddy: Tasks

แผนลงมือสร้าง แยกเป็นงานเล็กที่ตรวจได้ทีละงาน อ้างอิงศัพท์จาก @CONTEXT.md หน้าตาและพฤติกรรมจาก @design.md และกฎการเขียนโค้ดจาก @CLAUDE.md ไฟล์นี้ไม่ซ้ำเนื้อหาของสามไฟล์นั้น ถ้าข้อไหนขัดกัน ให้ยึดสามไฟล์นั้นก่อน

ทำตามลำดับ ทำทีละงาน และติ๊ก `[x]` เมื่อผ่านเกณฑ์ "เสร็จเมื่อ" ของงานนั้นแล้วเท่านั้น

## กติกาที่ใช้กับทุกงาน

- นิยามคำว่า "เสร็จ" ตาม CLAUDE.md: `npm run lint` และ `npm run build` ผ่าน, เปิด http://localhost:3000 แล้วลองกดตามที่งานนั้นระบุได้จริง, ตอบสรุปสั้นๆ ว่าแก้ไฟล์อะไร
- ก่อนเขียนโค้ดที่ใช้ Next.js, Tailwind หรือ Supabase ให้ดึงเอกสารเวอร์ชันปัจจุบันผ่าน Context7 ก่อนเสมอ (Tailwind แต่ละเวอร์ชันตั้งค่า theme ต่างกัน)
- ห้ามติดตั้ง package ใหม่โดยไม่ถามก่อน ห้ามอ่านหรือแสดงค่าใน `.env.local`
- JavaScript เท่านั้น ไม่ใส่ semicolon ใช้ single quote ข้อความบนหน้าเว็บเป็นภาษาไทย ชื่อตัวแปรและฟังก์ชันเป็นภาษาอังกฤษ

# Phase 2: Supabase และล็อกอิน

เริ่มเมื่อ Phase 1 ผ่าน T11 แล้วเท่านั้น ข้อมูลเดิมใน localStorage ไม่ย้ายขึ้น เริ่มใหม่

## P2-1. ตั้งค่า Supabase (Owner ทำเอง)

งานนี้ Owner ทำใน Supabase dashboard ผมช่วยได้แค่เป็นรายการตรวจ:

- [ ] มีโปรเจ็กต์ Supabase สำหรับแอปนี้
- [ ] สร้างบัญชี Owner (อีเมล+รหัสผ่าน) ด้วยตัวเอง
- [ ] **ปิดการสมัครสมาชิก (sign-ups)** ในการตั้งค่า Auth
- [ ] ใส่ URL และคีย์สาธารณะ (publishable/anon) ใน `.env.local` เอง ผมไม่อ่านและไม่แสดงค่าในไฟล์นี้

**เสร็จเมื่อ:** Owner ยืนยันว่าทำครบสี่ข้อ

## P2-2. ติดตั้ง Supabase client

- [ ] **ขออนุญาตก่อน** แล้วติดตั้ง `@supabase/supabase-js` (ไม่ติดตั้งอย่างอื่น เช่น auth helpers ที่ไม่จำเป็น)
- [ ] สร้างไฟล์ที่สร้าง client กลางไฟล์เดียว และเพิ่มลงหัวข้อ "โครงสร้างไฟล์" ใน CLAUDE.md

**เสร็จเมื่อ:** lint และ build ผ่านโดยยังไม่มีหน้าจอเรียกใช้ และคีย์ที่ใช้ฝั่งเบราว์เซอร์เป็นคีย์สาธารณะเท่านั้น (ห้ามคีย์ service role อยู่ในโค้ดหรือ `NEXT_PUBLIC_*`)

## P2-3. สร้างตาราง `loans` และ Row Level Security

- [ ] **ขออนุญาตก่อนรันกับโปรเจ็กต์จริง** ตารางมีคอลัมน์: `id`, `item`, `borrower`, `borrowed_date`, `due_date`, `return_date` (สามคอลัมน์วันที่เป็นชนิด `date`, `return_date` เป็น null ได้), `user_id` (ค่าเริ่มต้นคือผู้ล็อกอินปัจจุบัน) และคอลัมน์ที่ระบบต้องใช้อื่นๆ ตามที่เอกสาร Supabase แนะนำ
- [ ] บังคับ `due_date >= borrowed_date` ระดับฐานข้อมูลด้วย เพื่อไม่ต้องพึ่งการตรวจฝั่งหน้าจออย่างเดียว
- [ ] เปิด RLS และตั้งนโยบายให้อ่าน เพิ่ม แก้ ลบ ได้เฉพาะแถวที่ `user_id` ตรงกับผู้ล็อกอิน

**เสร็จเมื่อ:** ตารางและนโยบายถูกสร้างแล้ว และตรวจได้ว่า RLS เปิดอยู่ (ผ่านเครื่องมือตรวจความปลอดภัยของ Supabase ถ้ามี) ก่อนมีข้อมูลจริงใดๆ

## P2-4. `lib/auth.js`

- [ ] ฟังก์ชัน `getSession`, `signIn`, `signOut` เป็น `async` ตาม design.md
- [ ] `signIn` ที่ผิดพลาดทุกกรณีต้องให้ข้อความเดียวกัน: "อีเมลหรือรหัสผ่านไม่ถูกต้อง" ไม่บอกว่าผิดช่องไหน

**เสร็จเมื่อ:** lint และ build ผ่าน (ตรวจการทำงานจริงในงาน P2-5)

## P2-5. หน้าล็อกอินและประตูเข้าแอป

- [ ] ยังไม่ล็อกอิน: แสดงหน้าล็อกอินแทนหน้ารายการ (ชื่อ "Borrow Buddy", ช่อง "อีเมล", "รหัสผ่าน", ปุ่มหลัก "เข้าสู่ระบบ" ใช้ธีมเดียวกับหน้าอื่น) ข้อความผิดพลาดขึ้นใต้ฟอร์ม ไม่ใช้ `alert()`
- [ ] ตอนกำลังตรวจ session ให้แสดง "กำลังโหลด" ไม่แวบหน้าล็อกอิน
- [ ] ล็อกอินแล้ว: หัวเว็บมีปุ่มรอง "ออกจากระบบ" ข้างปุ่ม "เพิ่มรายการยืม"
- [ ] Session หมดอายุระหว่างใช้งาน: กลับหน้าล็อกอินพร้อม "เซสชันหมดอายุ กรุณาเข้าสู่ระบบอีกครั้ง"
- [ ] ไม่มีหน้าสมัครสมาชิกและไม่มีหน้ารีเซ็ตรหัสผ่านในแอป

**เสร็จเมื่อ:** ล็อกอินด้วยรหัสผิดแล้วเห็นข้อความที่ถูกต้อง ล็อกอินด้วยรหัสถูกแล้วเห็นหน้ารายการ ออกจากระบบแล้วกลับหน้าล็อกอิน รีเฟรชแล้วยังล็อกอินอยู่

## P2-6. เปลี่ยน `lib/loans.js` ไปใช้ Supabase

- [ ] แก้เฉพาะ `lib/loans.js` ชื่อฟังก์ชันและรูปแบบข้อมูลที่คืนต้องเหมือน Phase 1 ทุกอย่าง (camelCase) แปลงชื่อคอลัมน์ snake_case ในไฟล์นี้ และ `user_id` ไม่หลุดออกไปถึงหน้าจอ
- [ ] `markReturned` ตั้ง Return Date เป็นวันตามปฏิทินของเครื่องเหมือนเดิม (ไม่ใช้เวลาของเซิร์ฟเวอร์ที่อาจคนละวัน)
- [ ] หน้าจอที่แสดง Loan ต้องไม่ต้องแก้ ถ้าต้องแก้ ให้หยุดและรายงาน เพราะแปลว่า Phase 1 ทำผิดข้อกำหนด
- [ ] ข้อผิดพลาดจาก Supabase (เครือข่ายหลุด, session หมดอายุ) ต้องขึ้นเป็นข้อความไทยบนหน้า ไม่ใช่หน้าขาว

**เสร็จเมื่อ:** เดินสถานการณ์ทั้งหกของ T11 ซ้ำกับ Supabase แล้วผ่านทั้งหมด และตรวจใน dashboard ว่าแถวที่สร้างมี `user_id` ของ Owner

## P2-7. ตรวจรับ Phase 2 (ความปลอดภัย)

- [ ] เรียกอ่านตาราง `loans` ด้วยคีย์สาธารณะโดย**ไม่ล็อกอิน** ต้องได้ข้อมูลว่าง และเพิ่ม/แก้/ลบต้องถูกปฏิเสธ
- [ ] ยืนยันว่าสมัครสมาชิกใหม่ผ่านแอปหรือ API ไม่ได้ (sign-ups ปิดอยู่)
- [ ] ค้นในโค้ดว่าไม่มีคีย์ service role และไม่มีค่าจาก `.env.local` ถูก commit
- [ ] `npm run lint` และ `npm run build` ผ่าน

**เสร็จเมื่อ:** ผ่านทุกข้อและ Owner ลองใช้เองแล้วยืนยัน

## ข้อที่ยังไม่ได้ตัดสินใจ

1. **Return Date ก่อน Borrowed Date** (T9): ตอนแก้ Loan ที่ Returned ควรห้ามหรือไม่ design.md ยังไม่ระบุ ข้อเสนอคือห้าม
2. **ไฟล์ `lib/loan-utils.js`** (T4): ไม่มีในโครงสร้างไฟล์ของ CLAUDE.md ข้อเสนอคือเพิ่มไฟล์นี้และอัปเดต CLAUDE.md
3. **ข้อมูลเดิมใน localStorage ตอนขึ้น Phase 2:** ไม่ย้ายขึ้น Supabase แต่จะลบคีย์เดิมทิ้งหรือปล่อยไว้เฉยๆ ข้อเสนอคือปล่อยไว้ ไม่อ่าน ไม่ลบ
4. **การทดสอบอัตโนมัติ:** CLAUDE.md ไม่ได้กำหนด test framework แผนนี้ใช้ lint, build, สคริปต์ Node สั้นๆ สำหรับตรรกะวันที่ (T4) และลองกดจริง ถ้าอยากได้ test framework ต้องอนุมัติการติดตั้งก่อน
5. **การนำขึ้นออนไลน์ (hosting):** ยังไม่เคยคุยกัน อยู่นอกแผนนี้ ต้องตัดสินใจก่อนเริ่ม Phase 2 เพราะ Owner จะใช้ Supabase จากมือถือได้จริงก็ต่อเมื่อเว็บออนไลน์แล้ว
6. **ADR:** การย้ายจาก "เก็บในเบราว์เซอร์ ไม่มีบัญชี" ไปเป็น "Supabase พร้อมล็อกอิน" เข้าเกณฑ์เขียน ADR ยังไม่ได้เขียน รอ Owner สั่ง
